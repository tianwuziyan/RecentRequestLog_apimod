# Add record text export

## Goal

让用户可以直接保存某条请求记录的文本内容，便于在插件面板外阅读、归档或继续处理。每条记录在“查看全文”和“删除”之间增加“导出文本”操作。

## Confirmed Facts

- 这是一个单仓库的浏览器端 SillyTavern 扩展，主要实现位于 `index.js`，样式位于 `style.css`。
- 记录操作按钮由 `renderPanelContent()` 生成，事件由 `bindListEvents()` 绑定。
- “查看全文”打开后默认显示的请求内容由 `getReadContent(record, 'formatted')` 返回；导出必须使用这一默认格式，不使用点击 `{}` 后的原始请求体格式。
- 返回内容独立存储在 `record.reply` 中，返回消息的角色为 `response`，正文位于 `record.reply.content`；没有已挂载返回时 `record.reply` 为 `null`。
- 记录只存在于当前页面内存，不涉及持久化、网络接口、请求捕获或 API-mode 定制逻辑。

## Requirements

1. 在每条记录现有“查看全文”和“删除”按钮之间增加一个“导出文本”按钮，并沿用现有记录操作区的交互、主题和移动端尺寸规则。
2. 点击按钮后下载“查看全文”里默认显示格式对应的一个 `.txt` 文件；不随用户此前是否切换过 `{}` 原始格式而改变。
3. 当该记录存在非空 `record.reply.content` 时，再下载一个独立的 `.txt` 文件，内容为该记录 `RESPONSE` 消息的原始文本。
4. 当记录没有 `RESPONSE` 内容时，只下载全文文件，不创建空的 RESPONSE 文件。
5. 导出的文件名应包含可识别的记录信息和内容类型，并清理文件系统不允许的文件名字符；不改变记录内容、顺序、折叠状态或现有操作行为。
6. 同步更新会介绍记录操作的用户文档和产品引导文案，使新增操作不再被遗漏。

## Acceptance Criteria

- [x] 每条展开记录的按钮顺序为“查看全文 → 导出文本 → 删除”；点击导出不会触发记录展开/折叠或删除。
- [x] 有 RESPONSE 的记录一次点击产生两个 `.txt` 下载：全文文件内容等于“查看全文”打开后默认显示的内容，RESPONSE 文件内容等于 `record.reply.content`。
- [x] 没有 RESPONSE 的记录一次点击只产生全文 `.txt` 下载。
- [x] 文件名在包含角色/时间等可识别信息的同时，不含 `< > : " / \\ | ? *` 等非法文件名字符。
- [x] 桌面端、移动端以及明亮/暗色主题下按钮均沿用现有操作区布局，不破坏搜索、查看全文和删除操作。
- [x] `node --check index.js`、`node --check tour.js`、`git diff --check` 通过；相关 README 与引导文案和最终实现一致。

## Out of Scope

- 不导出原始 JSON 请求体，不新增导出格式选择器或压缩包。
- 不改变现有“查看全文”覆盖层、复制、请求捕获、回复解析、数据模型和 API-mode 定制行为。
- 不添加记录持久化、批量导出或跨记录导出。

## Open Questions

无。文件名采用插件名 + 记录时间/角色 + `全文` 或 `RESPONSE` 的可读方案；这是实现细节，不改变用户可见的导出内容。
