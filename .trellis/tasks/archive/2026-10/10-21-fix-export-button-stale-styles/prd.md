# Fix export button stale Shadow DOM styles

## Goal

修复导出按钮在记录折叠态仍显示、展开后样式不统一的问题，让它恢复与查看全文、删除等记录操作按钮一致的 UI 行为。

## Background

- 用户报告两个可见回归：记录折叠时导出按钮仍在；记录展开后导出按钮呈现与其他操作按钮不同的原生白色样式。
- 当前源码的记录操作区在 `index.js:4757-4759` 使用 `.rlog-export-text-btn`；`style.css:1062-1080` 已将该类加入操作按钮基础样式，`style.css:1106-1115` 已将其加入折叠态隐藏规则。
- 面板使用 Shadow DOM。`index.js:6723-6733` 会从宿主已加载的插件 CSS `<link>` 序列化样式并通过 `selfCssTextCache` 复制到 Shadow DOM；如果宿主仍保留旧版 `style.css`，新按钮类的基础和折叠规则不会进入影子根。
- 上述源码规则与用户看到的两个现象不一致，因此“旧版 CSS 被复制/缓存”是当前最可能的根因；是否需要缓存失配自修复，需在实现中沿现有样式注入路径验证后确定。

## Requirements

- 记录折叠时导出按钮必须隐藏；记录展开时必须显示。
- 展开状态下导出按钮必须使用独立的 `.rlog-export-text-btn` 类，但与查看全文、删除等记录操作按钮保持相同的尺寸、背景、边框、颜色、字号、间距和 hover 行为，不出现浏览器原生白色按钮样式。
- 修复必须覆盖 Shadow DOM 实际使用的样式路径，不能只在当前静态 `style.css` 中重复已有选择器；应兼容宿主仍复制旧版 CSS 的情况。
- 导出按钮使用适合文本文件下载的 Font Awesome `file-arrow-down` 图标；保持图标映射、点击事件、格式化全文/可选 `RESPONSE` 导出内容、文件命名和事件传播行为。
- 不改变查看全文、删除及其他记录操作按钮的既有显示和行为。

## Acceptance Criteria

- [ ] 记录处于折叠态时，导出按钮不可见；展开后导出按钮出现。
- [ ] 展开态下导出按钮与查看全文、删除按钮在视觉样式和布局上统一，且 hover 状态一致。
- [ ] 刷新/重新加载扩展后，Shadow DOM 仍使用包含导出按钮规则的当前样式，不依赖用户手动清理浏览器缓存。
- [ ] 导出按钮点击仍生成格式化全文，并在存在非空 `RESPONSE` 时额外生成 `RESPONSE` 文本。
- [ ] 通过 JavaScript 语法检查、CSS/静态断言和差异检查；无可用的 npm lint/type/test runner 时明确记录。
- [ ] 相关 Markdown/规范文档与最终实现一致。

## Out of Scope

- 不重做记录操作区布局，不更换导出图标，不修改导出文件内容或命名。
- 不改变其他按钮的折叠态显示、操作事件或主题配色。
- 不复用查看全文按钮的语义类或点击处理器。
- 不引入新的 CSS 框架、图标依赖或复杂的样式注册层；样式失配修复应限制在现有 Shadow DOM 样式注入路径。

## Risks and Deferred Validation

- 当前用户报告来自实际宿主，而本地仓库没有浏览器自动化验收环境；最终仍需在 SillyTavern 刷新扩展并分别验证折叠/展开状态。
- 旧版 CSS 兼容方案不能让导出按钮复用“查看全文”的语义类或点击处理器。

## Open Questions

- 无阻塞性产品问题。技术实现应优先复用现有 Shadow DOM 样式注入路径，以最小变更解决旧样式失配。
